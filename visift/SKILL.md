# Visift

## Overview

目标是**把图片里的内容整理成能直接阅读、保存和核对的文字**；默认文章，按用户要求选笔记、字段表格或严格转录。
流程：确定范围、形式与交付 → 还原层级 → 按模式保留内容 → 判断跨图关系 → 核对缺口 → 组织正文 → 核对交付。
输出中的每个知识点都必须能在原图指认出来；补出的字必须标注。

**默认整合文章**：整理模式按主题或流程组织，不逐图转储；笔记和字段表格按所选结构输出。严格转录保持原图顺序，不做语义去重或推测补字。

**冲突裁决顺序：忠实 > 可读 > 简洁**。忠实与可读冲突时选忠实，宁可留 `[无法辨认]`；为读得顺可以重复用词，不省字；原文别扭就照抄别扭，不修正。

## 输出语言

- **正文语言 = 图片原文的语言**：中文图出中文文章，英文图出英文文章，中英混排保持混排。不翻译——术语、专有名词、代码、报错原样保留；原文语言判不出（只有代号或极短句）时按可见字符原样写并在缺口说明。
- **「整理说明」、拒绝理由、缺口与存疑提示用用户对话的语言**，可以与正文语言不同。
- 用户明确要求换成另一种语言成文 = 翻译请求：可以做，但整篇按翻译稿处理，开头声明「本文为翻译稿，非原文措辞」，`〔〕` 与 `[无法辨认]` 照旧标注。

## 标注符号（只用这五个，不自造新标记）

| 符号 | 用在哪 |
| --- | --- |
| `[无法辨认]` | 正文内容缺字且不满足第 6 步的补全条件（遮挡 / 反光 / 字迹不清） |
| `[内容被截断]` | 图片边缘切掉字、半行，或句子未结束；标在断处，严禁补完 |
| `[原文如此]` | 原图确实写错的错别字、病句；先照抄原文再紧跟此标记，不改动原文 |
| `〔〕` | 仅限第 6 步允许的保守补全，只包住补出来的字（`需〔保〕留`），须逐条登记进「整理说明」 |
| `（空）` | 表格单元格里原文确实留空；与"看不清"含义不同，不可混用 |

## 必须先拒绝的输入

| 输入 | 处理 |
| --- | --- |
| 视频、动图 GIF、多帧动画 | 说明只处理静态图片，不逐帧猜内容 |
| 纯装饰图、插画、Logo（无可辨认文字） | 说明"图中没有可提取的文字"，不用画面描述凑篇幅 |
| 物体 / 人物 / 场景识别 | 不属于文字提取，说明边界后停止 |
| 需外部知识才能读懂的残缺内容 | 只写可见部分并标缺口，不解释、不续写 |
| 图片不可读（损坏、分辨率过低） | 说明无法可靠辨认，建议提供更清晰的图 |

## 执行步骤

### 1. 获取图片与确定任务

用宿主可用的图片读取方式实际查看；图片已在对话中附带时直接看，不假定特定工具名。
**未真正看到图片时不得输出任何"整理结果"** —— 只说明需要图片文件或重新上传。
从用户请求确定范围与形式：默认主体内容的整合文章；“笔记 / 分点”选笔记，“按字段列成表格”选字段表格，“逐字 / 原样转录”选严格转录。歧义会明显改变取舍且无法判断时才询问。
正文形式、转录例外和交付细则见 `references/image-types.md` 的「输出选择与交付」，非默认形式或文件交付前先读。默认只在对话中输出；明确保存或导出才生成 Markdown 文件。
用户说“还没发完 / 等发完再整理”时仅确认收到的范围，等“发完了 / 开始整理”等指令；未要求等待则正常处理。分批上传、超长输出或追加修正时先读 `references/dedup-and-rewriting.md` 的「分批上传与后续修正」。

### 2. 逐区扫描（内部动作，不作为输出）

按阅读顺序分区，记录：逐字的文字内容（含数字、单位、标点、代码、公式）；层级线索（字号、加粗、颜色、编号 `1.` `一、` `①`、缩进、分隔线、表格线、列头）；元素类型（标题 / 正文 / 列表 / 表格 / 代码块 / 引用 / 图注 / 页眉页脚 / 水印 / UI 控件）。
然后列一张内部**内容清单**：每条记录原文、图号（同一批跨消息连续编号，不重编号）、区域与可见文字锚点，以及去向（保留 / 排除及原因 / 被哪条覆盖 / 未解决缺口）；整理依清单聚合，转录按原图顺序。
多语言混排、竖排、分栏时保持原边界，不跨栏拼句；正文用什么语言见「输出语言」。

**类型分流**：输入属于滚动拼接长图、聊天截图、手写笔记、拍照的屏幕或 PPT、表格、代码、扫描书页或 PDF、网页截图、图表这几类时，先读 `references/image-types.md` 的对应小节，把那里的额外动作叠加到本流程（多类可叠加就都读，冲突时取更保守的一方）。看不出类别就按主流程走，不必勉强归类。

### 3. 区分内容文字与干扰文字

先保留任务所需的按钮、菜单、说话人、时间、署名与来源；页码等定位线索可仅留在内部清单。严格转录保留指定范围全部可见文字，未限定区域时范围为整图，不做干扰过滤。
整理模式对其余文字做**连贯性测试**：它属于句子主干或必要修饰，还是叠加层？判定线索依次为**跨图重复出现 > 视觉层级异常（透明 / 压层 / 贴边） > 语义不连贯**，命中两条且与任务无关才排除。
干扰文字不写进正文、也不标 `[无法辨认]`（噪声不必逐字确认），只在「整理说明」的「未采纳」按类别计数；不解释它是谁、不补充关于该账号或平台的任何背景。
涉及任务相关的界面文字，或拿不准某串字是否干扰时，先读 `references/interference-text.md`；存疑文字保留并在「整理说明」注明位置。

### 4. 保留任务范围内的独有信息

保留：定义、结论、因果、条件与限制、数值与参数、步骤、方法、术语、原文给出的示例与边界情况。
不因篇幅短、像旁支或不够重要而删除独有信息。整理模式仅排除与任务无关的寒暄、推广、广告等并登记原因；补充示例、限定条件、例外和归属必须保留。严格转录跳过筛选；字段范围以用户明确要求为准。

### 5. 判断跨图关系

以下聚合与删重仅限整理模式，多图比对先读 `references/dedup-and-rewriting.md`：区分重复、互补、冲突或待核对、同段清晰度差异。严格转录跳过聚合与删重，核对只用于原位置的辨认。
**只做删除与择一，不做改写拼接**——须条件与归属兼容且信息被完整覆盖，才可删除重复；两条各取一部分拼成新句属编造，无法判定谁更完整时两条都保留。
互补内容按主题聚合并保留原句；不同条件或版本分别保留；相同条件下的冲突不裁决，正文保留双方原文，在「整理说明」登记差异与来源；条件不明则记为待核对。
标题与正文、目录与正文、相邻步骤、表格数据行不按修辞重复删除；同段文字有清晰图时转第 6 步核对，禁止拿不同版本相互补字。

### 6. 缺口核对与保守补全

遇到缺口先读 `references/gap-filling.md`：必要时局部复查；其他图可确认是同一版本、同一片段且缺口文字清楚可见时，照抄该片段并登记核对来源。这是有图可核对的转录，不用 `〔〕`，不算推测补全。
无可见原文可核对时，严格转录直接保留缺口；整理模式只补 1–2 个非事实性字，且为功能成分或高频搭配中的缺字、上下文唯一支持、不改变意思条件范围结论。完整实词、整句或有第二解时不补。
**绝对不许推测补出**：数字、单位、金额、时间、日期、人名、地名、机构名、版本号、专有名词、否定词、条件与程度词（如果 / 必须 / 仅 / 可能 / 不）、结论性表述。
推测补出的字用 `〔〕` 包住并逐条登记依据；未解决缺口记下图号、区域、邻近原文与原因，补图请求只针对需要核对的位置。

### 7. 按所选形式组织正文

- **形式与顺序**：文章按主题或流程整合；笔记保留原有层级与原句，不默认压缩摘要；字段表格按原文或用户指定字段组织，记录与条件不能错配；严格转录保留图片与图内阅读顺序。
- **标题与字段名**：使用原文词汇；字段名也可由用户明确指定，属于组织标签，不冒充原文。无可用标题就省略，不发明“阶段一”“核心要点”；缺失字段与模糊、原有空格分别处理，见输出细则。
- **衔接**：保留原句已有的逻辑词（"然后""确定需求之后"），不把别处的连接词搬来连接两句，不添加因果解释（"这是因为""由此可见""也就是说"）。
- **人称语气**：跟随原文，不改写主体（原文"我想做一个 App"就保持这口吻，不要变成"用户希望开发一款…"的说明书腔）。
- **列表与表格**：原有表格、代码、流程和零散要点保留适合的结构；文章以段落为主，笔记以层级要点为主，不为统一版式损失信息。
- **篇幅**：不扩写。整合后长度应接近原文有效内容的量；有效内容少，文章就短，这是正确结果。
- **来源标注**：默认不在正文标「（图 3）」；用户要求可追溯时，才在文末附完整来源对照表。缺口、跨图核对和差异的必要定位始终写进「整理说明」。

### 8. 自检（输出前必做）

逐条回看原图核对：

1. 除允许补字与用户指定的组织标签外，每个句子、数字、术语能否定位到原图？指不到 → 删除；范围内每条独有信息是否都有正文去向？遗漏 → 补回；转录还须保留重复和原顺序。
2. 整理模式是否混进无关干扰或误删任务所需的按钮、说话人、时间？→ 修正；严格转录是否误用了过滤规则？→ 恢复指定范围内原文。
3. 有没有加原文没有的解释、结论、背景、小标题、总结句、过渡句？有没有把原文的模糊或条件性表述写成确定表述（"可能有效"→"有效"属篡改）？
4. `〔〕` 是否符合唯一解并已登记？跨图核对是否来自可确认的同段可见原文？仍不可读或截断的地方是否留了缺口？表格原有空格是否误写成 `-` 或"无"？
5. 整理模式是否只删完整覆盖的重复？独有细节、不同条件或版本、冲突双方是否保留并定位？严格转录是否误做了语义去重或推测补字？
6. 层级、编号、原表行列与条目数量是否对应？字段表格的对象、字段、条件是否正确配对，未提供字段是否被误填为猜测值？
7. 正文是否符合所选形式、保留量与交付方式？笔记不强改成段落，转录不强行成文；文件必须复用同一份正文和说明，写出后回读核对，成功才交付链接。

## 统一输出与交付

统一外层为：原文标题（可省）→ 所选形式的正文 → 分隔线 → 整理说明。完整模板与按需显示规则见 `references/image-types.md` 的「统一外层与整理说明」。
正文保留原文；统计、补全、核对、缺口、差异、字段缺失与来源定位写在整理说明中。没有对应情况就省略；缺口只计尚未解决的正文缺口，计数须与当前版本一致。
默认对话交付，不自动创建文件。明确要求保存或导出时生成 UTF-8 Markdown 文件，复用当前正文与说明，校验后返回文件链接和简短说明；不重复输出全文，不把保存理解为上线发布。
文件名、位置、同名冲突、后续更新与宿主无写文件能力时的处理，按输出细则执行。HTML 与 JSON 不属于本版约定的交付格式，不自动转换。

## 分批与追加

依据文字密度、表格或代码复杂度、主题边界和预计输出长度分批，不按固定张数切分。对话分批时标明实际处理与待处理范围，每批后等“继续”；文件能容纳完整内容时内部处理分段，交付一份完整文件。
同一批维持稳定图号、已处理范围、待处理范围、缺口和待整合修订；用户尚在上传时不输出阶段性成稿，不把“继续”误当成新的整理任务。
追加默认更新完整结果，沿用已选正文形式和交付方式；清晰补图只修复对应位置，用户只改某处时保留其余定稿内容。跨批替换、文件局部更新和原图不可访问的具体处理见 `references/dedup-and-rewriting.md` 的「分批上传与后续修正」。

## 硬性规则

- 不编造：不补充图片外的背景知识、不写"通常来说…"、不替原文总结观点、不做第 6 步允许范围之外的任何补全。
- 不美化措辞：原文口语就保留口语，原文感叹号照留，原文错别字照抄并加 `[原文如此]`。
- 不改写数字与术语：单位、量词、正负号、上下标、版本号逐字保留。
- 图表中的文字（标题、坐标轴标签、图例、刻度、数据标注）属于内容，照抄进文章；但**不推断趋势、不描述图形形状、不解读含义**，除非原图文字本身写了结论。
- 文章化不等于创作：结构调整只做重排与择一删除，不得新增概念、不得拔高结论、不得补写"总结段"。

## 常见错误

| 错误 | 正确做法 |
| --- | --- |
| 默认整理模式下，14 张图输出 14 个「### 图 N」小节 | 按主题或流程整合；只有严格转录才保留逐图顺序 |
| 操作教程里的按钮或聊天里的说话人被当装饰删除 | 按任务保留有用文字与归属，只过滤无关干扰 |
| 「复述＿」既可能是需求也可能是内容，仍选中性词补入 | 有第二解就留 `[无法辨认]`，不能以中性为由猜字 |
| 原文没写"阶段" → 加小标题「阶段一：需求确认」 | 用原文词作标题，或直接连续成段 |
| 图片右边缘切掉半句 → 按常识把后半句写完 | 停在断处标 `[内容被截断]`；不确定就整条留作缺口 |
| 手写笔记只有词组和箭头 → 硬凑成三段通顺文章 | 降级输出清单或要点，并在「整理说明」写明"因手写零散未成文" |
| 折线图 → "呈上升趋势，说明业务向好" | 照抄轴标签与数据标签；结论只在原文有写时才出现 |
| 截图 3 行内容 → 扩成 5 段漂亮笔记 | 文章就是 3 行的量；无实际缺口则不列缺口项 |
