# 干扰文字识别线索

整理模式第 3 步涉及任务相关的界面文字或难以区分的干扰时读。先按 `SKILL.md` 判断任务相关性，再看连贯性与视觉线索；命中两条线索且与任务无关才排除。严格转录保留指定范围全部可见文字，不执行本节过滤。

## 先判断文字在当前任务里的作用

- 用户明确要整理的对象优先保留：操作教程的按钮与菜单、讨论记录的说话人与回复关系、广告截图中用户指定提取的文案，都不能仅按元素类别排除。
- 时间戳可能用于还原讨论顺序、区分版本或识别同一消息；需要这些关系时保留。与任务无关的设备状态栏时间才归装饰。
- 作者署名、发布时间、资料来源属于内容归属。页码、重复标题等可在内部清单中用于排序和定位，即使最终正文不展示也先保留这些线索。
- 主题相似、跨图重复、位于边缘均不能单独证明是噪声；重复的表头、必要提示、步骤编号仍可能承载内容。
- 同一元素兼有界面和内容作用时按内容处理；用途不明时保留，并在整理说明中注明位置和存疑原因。

## 各类干扰的识别线索

| 类型 | 识别线索 |
| --- | --- |
| 水印、账号名、UP 主 / 博主署名 | 半透明或描边字；压在标题、主体或人脸之上；字号与正文不一致；**多张图重复出现同一串**；常与平台名连写 |
| 平台标识与 Logo 字样（bilibili、微信、抖音等） | 图形化字样而非正文字体；固定在某个角落；与当前主题无关；多张图位置一致 |
| 弹幕、评论浮层、跑马灯 | 悬浮在画面中部或任意高度；没有排版层级；语句彼此不连贯；同屏出现大量短句 |
| 可能的界面装饰 | 与当前任务无关的状态栏时间与电量、信号图标、按钮文案、菜单项、标签页标题、滚动条、进度条百分比、播放控件、倍速与清晰度标记；先应用上节的任务例外 |
| 页眉页脚、页码、二维码提示、"扫码关注" | 每页都在固定的边缘位置；内容跨页不变 |
| 与主题无关的引流文案 | 群号、微信号、"三连""关注""点赞"、优惠券、广告位、推荐关注列表 |

## 判定时最容易搞错的三种情况

- **压在正文上的半透明署名**：整理主体内容时通常属于干扰，即使带平台名也不应并进句子；用户明确要提取该署名时则保留可见文字，不补充身份背景。
- **文章的作者署名与发布时间**：这是内容（网页、公众号文章的排版层里有它）。与水印的区别——水印是压在图像之上的一层，署名在排版流之内。
- **图片里嵌套的另一张图上的水印**：内层图的文字若承载内容（例如截图里的标题），照抄；叠在它上面的署名仍按干扰处理。层级要分清，不要一并删掉。

## 处理动作

- 不写进正文，也不标 `[无法辨认]`——缺口名额只留给正文内容，噪声不必逐字确认。
- 在「整理说明」的「未采纳」项里按类别计数，例如「水印 / 账号名 1 处、平台标识 1 处」，让过滤动作可核对。
- 不解释它是谁、不补充关于该账号或平台的任何背景（那是图片外的知识）。
- 判断不了某串字是干扰还是内容时，**保留它进正文**并在「整理说明」注明存疑，不静默删除（静默删错等于丢信息）。
- 各图片类型特有的界面元素（聊天的时间戳分组、浏览器的地址栏与 Cookie 弹窗、编辑器的行号）见 `image-types.md` 对应小节。
