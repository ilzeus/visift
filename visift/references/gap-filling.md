# 缺口核对与保守补全

第 6 步的完整判定。遇到缺口或清晰补图时先读；先找可见原文，再判断是否允许推测补字。严格转录不做推测补字；用户明确省略整理说明时不新增补字，已有标记与依据按 `image-types.md` 的说明展示规则处理。两者仍可核对清晰原文。

## 定位与局部复查

- 缺口记录图号、区域、邻近可见原文、原因；表格加行列头，聊天加可见说话人或气泡位置。不编造像素坐标或行号。
- 对小字、数字、单位、表头、代码符号等疑点，若宿主支持，放大或查看局部后再核对。放大不能产生原图没有的细节，不使用生成式修复结果作为原文证据。
- 局部复查没有增加可辨信息时停止，保留缺口，不对同一像素反复猜读。宿主无局部查看能力时直接说明缺口，不假装执行了工具。
- 不因一处模糊而拒绝整组图片：先整理可读部分；补图请求指出具体图号、区域与邻近原文。

## 用另一张图核对可见原文

以下条件必须同时成立：

1. 有共同标题、连续重叠文字、表格行列身份等可见线索，足以确认同一对象、同一版本、同一片段；不能只因主题相似、模板相同或上传较晚就认定对应。
2. 原图缺口周围仍可辨认的文字与候选片段一致；已出现不同数值、否定词、日期或版本等实质差异时，转第 5 步登记差异，不相互补字。
3. 候选图中对应文字确实清晰可见，能指明位置；不能把两张图中都看不清的部分拼凑猜顺。
4. 保留原有条件、范围、单位和归属；采用候选图可直接读取的同一片段，不跨行、跨列或跨记录移植字符。

满足条件 → 照抄可见原文。这是核对转录，数字、日期等也须逐字抄自清晰图，不属于下面的推测补全，不用 `〔〕`。在「核对」中登记原缺口位置、清晰来源位置和恢复的原文片段。
图片边缘截断的内容，只有在存在可对齐的重叠文字且另一张图完整显示同一片段时才能恢复；不能仅凭上下页看似接续就拼句。
无法确认对应关系 → 保留原缺口；两边各自可读的独有内容仍照常整理，不丢弃、不互相替换。

## 无可见原文时：四条补全前提

1. **只缺 1–2 个非事实性字**。完整实词、整句或整行缺失不补；按原因标 `[无法辨认]` 或 `[内容被截断]`。
2. **补的是功能成分或原文高频搭配中的缺字**，不是事实性内容；常见搭配本身不足以成为补字依据。
3. **补入后不改变意思、条件、范围或结论**。
4. **上下文唯一支持该补法**；存在第二解就不补，不能以“更中性”或“更顺口”为由择一。

四条有一条不满足 → 不补。图片边缘切掉的内容不做推测补全，只能按上一节核对可见原文。

## 绝对不许推测补出的成分

数字、单位、金额、时间、日期、人名、地名、机构名、产品名、版本号、专有名词、否定词（不、未、无、非）、条件与程度词（如果、必须、仅、可能、一定）、结论性表述、比较关系（高于、低于、约、近）。
这些成分没有清晰原文依据时，按缺口原因标记；不能因熟悉背景、搭配常见或自称高置信度而推测。

## 补字判定示例（规则示例，非运行记录）

| 可用证据 | 做法 |
| --- | --- |
| 同段的另一张图清楚显示缺失文字，且满足核对条件 | 照抄原文，登记「核对」，不用 `〔〕` |
| “需＿留”缺一个字，完整上下文仅支持“保”，且满足其余前提 | 写“需〔保〕留”，登记唯一依据，置信度高 |
| “复述＿”可能是“需求”也可能是“内容” | 写 `[无法辨认]`，不设“中置信度也能补”的例外 |
| “预算 12＿ 元”没有可核对的清晰来源 | 保留“预算 12[无法辨认] 元”，不猜数字 |

## 登记与后续修复

- `〔〕` 只包推测补出的字，不包原有字；逐处登记位置、补了什么、唯一依据与“置信度高”。这只是规则判定，不是量化概率。
- 当前正文里的 `〔〕` 数量必须与补全登记一致；依据写在整理说明中，不插进正文句子。
- 后续清晰补图到来时，先用原缺口的图号、区域和文字锚点定位，再按核对条件确认。原图不可访问、位置有多个候选或对应不明时，请用户补发对应原图或指出位置。
- 有直接证据后，替换对应的缺口或先前补字；即使先前补字猜错，也只按可见原文修正，并在「核对」中写明更正。更新未解决缺口数及补全登记，保留本次核对来源，不改写其他段落。
- 未解决缺口仍逐处保留，噪声不计入缺口；正文原有空单元格使用 `（空）`。
- 不用补字挽救整句，不为消除缺口而猜字，不润色补全后的句子；缺口本身就是应保留的信息。
